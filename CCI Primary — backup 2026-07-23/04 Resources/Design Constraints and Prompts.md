Before writing code, generate 5 distinct creative directions.

Each direction must include:
1. Core visual metaphor
2. Layout structure
3. Interaction model
4. Motion language
5. Why this is not a standard landing page
6. Risks/tradeoffs

Reject any direction that uses:
- generic card grids
- basic hero sections
- simple icon rows
- alternating image/text blocks
- standard FAQ accordions as a main design feature
- stock academic imagery
- corporate blue gradients
- “clean modern SaaS” clichés

After generating the 5 directions, select the boldest practical option and implement that.

For coding mockups:
```
Implementation rules:
- Use a non-traditional page structure.
- Use scroll-driven storytelling.
- Use layered depth, parallax, or spatial navigation.
- Use at least one interactive system: map, simulation, timeline, node graph, command center, or explorer.
- Use distinct section silhouettes; no repeated card grids.
- Use motion intentionally with Framer Motion or GSAP-style sequencing.
- Use data visualization or scientific visualization as part of the design language.
- Use empty space, scale, depth, and contrast aggressively.
- Make the page feel custom-built for this subject, not reusable for any program.
```

Most effective prompt add-on:

```
Act like a senior creative director, not a frontend template generator. Your first job is to break predictable webpage patterns. If your design could be reused unchanged for a business school, nursing program, or SaaS product, reject it and try again.
```

And the blunt anti-pattern checklist:

```text
Self-check before finalizing:
- Is this just a hero section with cards below it?
- Could this same design work for any graduate program?
- Are the interactions decorative instead of meaningful?
- Does every section look like it came from the same template?
- Is the visual metaphor specific to advanced therapeutics?
- Would a user remember this page 10 minutes later?

If any answer is weak, redesign before coding.
```
